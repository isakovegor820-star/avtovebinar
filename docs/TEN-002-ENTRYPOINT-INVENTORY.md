# TEN-002 platform-wide tenant entry-point inventory

Проверено по маршрутам и worker entry points репозитория 2026-08-23. Эта матрица является обязательным deploy-review артефактом: новый внешний read/write/bulk/export/media/callback маршрут должен быть добавлен сюда до merge.

## Инварианты

- Tenant authority возникает только из проверенной `aspb_user_session`, membership, participant Registration/Grant либо из уже сохранённой tenant-qualified job/callback связи. `organizationId`, `webinarId`, `sessionId`, user ID, provider callback ID и storage key из запроса не выбирают tenant.
- Основная цепочка доверия — `Organization → Webinar → WebinarSession`; зависимые записи несут `organization_id`, а сервис повторно связывает ID в одном tenant query. Для legacy contour действует единственный bridge `org_aspb / webinar_aspb_legacy`; отдельной доменной модели нет.
- Foreign и unknown ID дают одинаковый безопасный `404` и code в tenant endpoints. Публичный каталог и export-фильтры возвращают одинаковый пустой результат, когда это уже опубликованный compatibility contract.
- Idempotency/deduplication tenant-qualified: uniqueness включает `organization_id` либо job/callback/preview сначала разрешается через tenant-owned parent. Audit получает тот же server-derived `organization_id`.
- `AdminUser` не является `User`: `/api/admin/**` принимает только действующую MFA AdminUser session; tenant OWNER/ANALYST/AUDITOR не получает platform access.

| STT/AI content worker | ContentJob → Transcript/MediaAsset/Webinar organization chain | production provider defaults unconfigured; fake only in tests; published projection is never inferred | tenant-scoped job, draft/published visibility and provider-neutral failure tests |
| Retention sweep | each row's stored tenant relation | no client input; legal hold and per-table retention policy applied before bounded deletion/anonymization | retention matrix/assertions and dry-run/audit tests |

## Database enforcement

Existing tenant tables retain composite/qualified unique constraints and scope triggers from TEN-002 migrations. Migration `20260823120000_analytics_moderation_platform` adds foreign keys and scope triggers so reports, events, correction requests/revisions, actions and audit parents cannot cross organizations; history tables reject update/delete. Application checks therefore cannot be bypassed by a direct inconsistent write.

## Completion rule

The platform-wide local rollout is considered implemented only while: this inventory matches the route list, all negative integration/browser tests pass on PostgreSQL, additive pre/postflight reports zero violations, and deploy-contract finds no missing migration. Real staging remains a separate Definition-of-Done gate.
