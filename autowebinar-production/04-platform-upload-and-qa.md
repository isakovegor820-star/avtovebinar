# Как загрузить автовебинар на платформу и протестировать

## 1. Подготовить видео

Финальный файл:

```text
webinar.mp4
```

Требования:

- MP4;
- H.264;
- 1920x1080;
- 25 или 30 fps;
- нормализованный звук;
- без точной даты в речи;
- длительность около 55-60 минут.

Положить файл сюда:

```text
crisis_premium/assets/webinar.mp4
```

После этого вебинарная комната автоматически использует файл:

```text
/crisis_premium/assets/webinar.mp4
```

## 2. Синхронизировать таймлайн

Таймлайн лежит в проекте:

```text
src/lib/webinarTimeline.ts
```

И в рабочем JSON:

```text
autowebinar-production/timeline-events.json
```

После финального монтажа нужно пройти видео и уточнить таймкоды:

- где начался блок рынка;
- где началась карта клиентов;
- где спикер говорит про АСПБ;
- где начинается партнерская цепочка;
- где начинается договор;
- где финальный CTA.

Если меняем `src/lib/webinarTimeline.ts`, нужно:

```bash
npm run build
npm test
```

Если таймлайн уже был засеян в базу для конкретной сессии, старые записи в БД могут остаться. Для локального теста проще пересоздать базу/сид или очистить `webinar_timeline_events` для тестовой сессии и запустить:

```bash
npm run seed
```

## 3. Проверить регистрацию

1. Открыть:

```text
http://127.0.0.1:5174/crisis_premium/index.html
```

2. Нажать регистрацию.
3. Заполнить форму.
4. Проверить, что открылась success-страница с token.
5. Проверить, что Telegram-кнопка ведет в бот уведомлений.
6. Перейти в вебинарную комнату.

## 4. Проверить вебинарную комнату

Тесты:

- без token комната закрыта;
- с token комната открыта;
- видео загружается;
- если файла нет, показывается заглушка;
- таймлайн отображается;
- при перемотке видео активный блок таймлайна меняется;
- форма вопроса отправляет вопрос в backend;
- заявка на партнерский договор отправляется в CRM.

## 5. Проверить админку

Открыть:

```text
http://127.0.0.1:5174/admin
```

Проверить:

- регистрация появилась;
- вопрос появился;
- заявка на договор появилась;
- Telegram click фиксируется;
- статус лида можно менять;
- заметка менеджера сохраняется.

## 6. Проверить Telegram

1. На success-странице нажать кнопку Telegram.
2. В Telegram нажать `Start`.
3. Бот должен привязать пользователя к регистрации.
4. Бот должен помнить имя/регистрацию через token.
5. В админке или базе должен появиться Telegram chat id.
6. Ручная рассылка из админки должна прийти подписчику.

## 7. Проверить email

Если `EMAIL_MODE=log`:

- после регистрации письмо должно появиться в консоли backend.

Если `EMAIL_MODE=send`:

- письмо должно реально уйти через SMTP.

Проверить письма:

- подтверждение регистрации;
- напоминание за 24 часа;
- напоминание за 3 часа;
- напоминание за 30 минут.

## 8. Итерации качества

### Итерация 1: смысл

Смотрим видео без платформы:

- понятно ли, что делает АСПБ;
- понятно ли, что делает партнер;
- нет ли лишней воды;
- есть ли желание оставить заявку.

### Итерация 2: монтаж

Смотрим как запись:

- нет ли затянутых пауз;
- не слишком ли много текста на слайдах;
- слышно ли спикера;
- нет ли устаревающих фраз.

### Итерация 3: платформа

Смотрим уже в комнате:

- таймлайн совпадает с речью;
- CTA появляются вовремя;
- вопросы и форма не мешают;
- финальный блок заявки заметен.

### Итерация 4: тестовый зритель

Дать посмотреть человеку не из команды и спросить:

1. Что такое АСПБ?
2. Что от тебя хотят после вебинара?
3. Почему тебе это может быть выгодно?
4. Что осталось непонятным?

Если человек не может ответить, дорабатываем сценарий.

## 9. Что показать команде

На встрече показываем не только сайт, а полный путь:

1. Лендинг.
2. Регистрация.
3. Success + Telegram-бот.
4. Вебинарная комната с видео.
5. Таймлайн.
6. Вопрос.
7. Заявка на договор.
8. Админка с новым лидом.
